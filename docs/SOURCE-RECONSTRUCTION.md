# Source reconstruction — M2 in progress

The Rust engine now accepts one explicitly supplied Solidity file, invokes a local `solc --standard-json`, and fills `EconomicFunction` records from the compiler AST. Run it with a `solc` executable installed locally:

```sh
cargo run -p security-engine -- tests/fixtures/VaultWithOracle.sol /path/to/solc
```

The command prints structured JSON IR. The library also exposes `reconstruct_source_file` and `reconstruct_from_ast_json` for callers that already have compiler output.

## Extracted now

- Named vault operations, previews, conversions and oracle price functions, classified from their names with `Inferred` confidence.
- Direct storage reads/writes, including compound assignments and indexed mappings, linked to source byte spans.
- Internal calls to functions in the same contract, explicit contract/address external calls, modifiers, arithmetic expressions and branch conditions.
- Oracle-call candidates when a price method is invoked on an oracle/feed/aggregator typed or named receiver.
- `delegatecall` receiver as a tentative proxy implementation candidate; ambiguity is recorded in `unresolved`.

Tests use AST snapshots generated by solc 0.8.37 from three small fixtures. They verify source locations, vault accounting relations, internal calls, branch conditions, and tentative proxy evidence. The command was also run against the local compiler for each fixture.

## Current limits

This slice accepts one source file with no imports. It records branch conditions, not a complete control-flow graph. It does not yet resolve inheritance, storage defined in base contracts, modifier bodies, transitive dataflow, or the actual implementation behind a proxy. Function-name classification may differ from economic behavior; such classifications are hypotheses for later analysis. AST/source matching checks offsets and function names, not a cryptographic source hash. Bytecode recovery, detectors, LLM calls, and Foundry validation remain future stages.

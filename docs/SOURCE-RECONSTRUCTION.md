# Source reconstruction — M2 in progress

The Rust engine now accepts one explicitly supplied Solidity file, invokes a local `solc --standard-json`, and fills `EconomicFunction` records from the compiler AST. Run it with a `solc` executable installed locally:

```sh
cargo run -p security-engine -- tests/fixtures/VaultWithOracle.sol /path/to/solc
```

The command prints structured JSON IR. The library also exposes `reconstruct_source_file` and `reconstruct_from_ast_json` for callers that already have compiler output.

## Extracted now

- Named vault operations, previews, conversions and oracle price functions, classified from their names with `Inferred` confidence.
- Direct storage reads/writes, including compound assignments and indexed mappings, linked to source byte spans.
- Internal calls to functions in the same contract, explicit contract/address external calls, modifiers, arithmetic expressions and branch conditions.
- Oracle-call candidates when a price method is invoked on an oracle/feed/aggregator typed or named receiver.
- `delegatecall` receiver as a tentative proxy implementation candidate; ambiguity is recorded in `unresolved`.
- A structural source control graph with `entry`, `exit`, and AST statement/expression nodes. Edges distinguish sequential flow, true/false branches, loop back edges, and exits. Each edge carries a source span. The extractor handles `if`, `return`, `revert` statements, `require`/`assert` guards, one ternary expression per statement, and `while` loops.

Tests use AST snapshots generated by solc 0.8.37 from three small fixtures. They verify source locations, vault accounting relations, internal calls, branch conditions, control edges, and tentative proxy evidence. The command was also run against the local compiler for each fixture.

## Current limits

This slice accepts one source file with no imports. The graph represents source syntax, not EVM basic blocks or all runtime paths. `for`, `do while`, `break`, `continue`, `try`, and inline assembly are recorded as unresolved, and their outgoing paths are omitted. Nested/multiple ternaries are also unresolved. The graph does not expand modifier bodies, model exception paths of arbitrary calls or arithmetic, or resolve inherited code. It does not yet trace data across functions or establish the actual implementation behind a proxy. Function-name classification may differ from economic behavior; such classifications are hypotheses for later analysis. AST/source matching checks offsets and function names, not a cryptographic source hash. Bytecode recovery, detectors, LLM calls, and Foundry validation remain future stages.
